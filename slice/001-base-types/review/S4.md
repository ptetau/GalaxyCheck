# Review of S4 (time types, containers, and automatic generation), round 1

- major: [requirement] src/GalaxyCheck/Gens/ReflectedGenHelpers/ReflectedGenHandlers/ImplementationReflectedGenHandler.cs:62 R32 (interfaces and base classes) and R33 (unions) work only at the top level. The handler returns a `OneOfGen<object>`, and each container handler casts its element generator to `IGen<TElement>`. `Gen.Create<List<IPet>>()`, `Gen.Create<IPet[]>()`, `Gen.Create<Dictionary<int, IPet>>()`, `Gen.Create<(int, IPet)>()`, and `Gen.Create<KeyValuePair<int, IPet>>()` each give the generator error "Object of type 'OneOfGen`1[System.Object]' cannot be converted to type 'IGen`1[IPet]'". `UnionReflectedGenHandler.cs:133` has the same fault: `Gen.Create<List<Pet>>()` fails for a union `Pet` on net11.0. So a `[Property]` parameter of type `List<IShape>` fails. Fix: build the pick generator with the element type T (for example `OneOfGen<T>` made with `MakeGenericType(type)`), as the other handlers return a typed generator.
- major: [requirement] src/GalaxyCheck/Gens/ReflectedGenHelpers/ReflectedGenHandlers/ImplementationReflectedGenHandler.cs:56 An interface fails on each sample when one of its concrete types has no usable constructor. With `Hamster(int)` and a sealed class `Hidden` that has only a private constructor, `Gen.Create<IPet2>()` gives "could not resolve type 'Hidden'" on 20 of 20 seeds, and no `Hamster` appears. A real assembly often holds such a helper type. Fix: leave out a found candidate whose generator is an error, and give the error that names T only when no candidate is left. Keep the error for a candidate that the user registered.
- major: [requirement] src/GalaxyCheck/Gens/TimeGens.cs:142 R11 (time types): `Gen.DateTimeOffset()` does not shrink toward the origin when the first failure is near an end of the range. The range of the offset choice depends on the UTC ticks, so the shrinker stops within one minute of the end. For the property "x < 2010-01-01T00:00+00:00", the counterexample is `9999-12-31T23:59:00+00:00` on seeds 0 to 5, not `2010-01-01T00:00+00:00`. For "x > 1990-01-01T00:00+00:00", it is `0001-01-01T00:00:59.9999999+00:00`, not `1990-01-01`. With bounds from 2000 to 2100 the same property shrinks correctly, and `Gen.DateOnly()` and `Gen.TimeSpan()` shrink correctly. Fix: make the meaning of the offset choice independent of the ticks, for example draw the offset from the fixed range -14 to +14 hours and clamp it after, so that a smaller tick value keeps a valid offset.
- minor: [architecture] src/GalaxyCheck/Gens/FactoryGen.cs:168 `IGenFactory.RegisterImplementations<T>` has a default body that throws `NotImplementedException("not implemented")`. That is a stub left in a public interface. An outside implementation of `IGenFactory` compiles and then throws at run time. Fix: remove the default body, or give a body that does the work.
- minor: [requirement] src/GalaxyCheck/Gens/DictionaryGen.cs:271 When the key generator has fewer distinct values than the minimum count, the run ends with `GenExhaustionException` and the default text "Exception of type ... was thrown". The run does not hang, but the message does not say why. `Gen.Dictionary(Gen.Boolean(), Gen.Int32()).WithCount(3)` gives this. Fix: give a message that names the minimum count and says that the key generator gave too few distinct keys.
- minor: [requirement] src/GalaxyCheck/Gens/Net11Gens.cs:51 R18 (.NET 11 types) asks R5 (full finite range) for `Decimal128`. The mantissa is at most `ulong.MaxValue`, so the largest finite value apart from `MaxValue` is about 1.8e6144. The values from 1.8e6144 to 9.9e6144 appear only as `MaxValue`. In 10000 values with the opt-out, the largest magnitude is 6.5e6136. Fix: draw a mantissa of up to 34 digits, as for the S3 finding on `decimal`.
