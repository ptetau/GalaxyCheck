# Review of S10 (the source generator and the reference pages), round 1

- major: [correctness] src/GalaxyCheck.SourceGeneration/GenCreateGenerator.cs:317 The generated code breaks the build of the user's project when a member of a record type can be null. For `record Nested(Address Home, Address? Work, int Id)`, the generator writes `new global::Address?(...)`, and the compiler stops with CS8628 ("Cannot use a nullable reference type in object creation"). `Gen.Create<Address?>()` fails in the same way. The `#pragma warning disable` of the generated file does not help, because CS8628 is an error. Fix: write the `new` expression with `named.WithNullableAnnotation(NullableAnnotation.NotAnnotated)`, and add a slice test with a nullable record member.
- major: [correctness] src/GalaxyCheck.SourceGeneration/GenCreateGenerator.cs:220 The generator writes code for two more kinds of type that it cannot compile. A record with a `required` member (`record Req(int X) { public required string Y { get; init; } }`) gives CS9035, and a `file record Local(int A)` gives CS0400, because the generated file cannot see a file-local type. The reflection path makes values for both types. Fix: report GCSG001 for a type with a required member and no `[SetsRequiredMembers]` on the constructor, for a file-local type (`IsFileLocal`), and for a constructor that is obsolete with an error.
- major: [requirement] src/GalaxyCheck.SourceGeneration/GalaxyCheck.SourceGeneration.csproj:1 R57 (source generator) asks for a source generator package, but the package does not carry an analyzer. `dotnet pack src/GalaxyCheck.SourceGeneration` writes `lib/netstandard2.0/GalaxyCheck.SourceGeneration.dll` and no `analyzers/dotnet/cs/` folder. A user who adds the package with a `PackageReference` gets no generated code, no GCSG001, and the reflection path in an AOT app. The slice tests pass only because each sample uses a `ProjectReference` with `OutputItemType="Analyzer"`. Fix: set `IncludeBuildOutput=false` and pack the assembly to `analyzers/dotnet/cs`, or ship it inside the `GalaxyCheck` package, and add a test that packs the generator and consumes it from a local folder.
- major: [correctness] src/GalaxyCheck/Gens/FactoryGen.cs:298 Suppression 1 (reflection fallback of `Gen.Create<T>()`) is not safe, because GCSG001 does not warn for three common call shapes. `Gen.Create<T>()` in a generic method with a type parameter T, `Gen.Factory().RegisterType(...).Create<Order>()`, and `Gen.Create<Order>().OverrideMember(...)` all compile with no GCSG001 and publish with no IL warning. In a NativeAOT program each one then fails at run time with "Error during generation: could not resolve type 'Order'". The user gets no sign of the problem until the published test runs. Fix: report GCSG001 for a `Create<T>()` call on `IGenFactory`, for an `OverrideMember` call on a `Gen.Create<T>()` result, and for a type argument that holds a type parameter. Keep the suppression only for the cases that GCSG001 covers, and document the three cases in `docs/generators.md`.
- major: [correctness] src/GalaxyCheck.SourceGeneration/GenCreateGenerator.cs:304 R58 (source generator parity) does not hold for a generic record whose member type is a type parameter. For `record Box<T>(T Value)`, `Gen.Create<Box<string>>()` with seed 0 gives 0 nulls in 200 values on the generated path and 35 nulls on the reflection path. The reflection path reads the nullability of the open definition, so it treats `T Value` as nullable. Also, the registry has one key for each run-time type. When a project asks for both `Box<string>` and `Box<string?>`, both registrations go to `typeof(Box<string>)`, and the last one wins. Fix: take the nullability of a member from `constructor.OriginalDefinition.Parameters[i]`, in the same way as `NullabilityInfoContext`, or report GCSG001 for a member whose declared type is a type parameter.
- minor: [correctness] src/GalaxyCheck/Runners/ExampleRenderer.cs:10 Suppression 2 (the failure report reads members by reflection) hides a bad report in NativeAOT. A failing `Gen.Create<Order>()` property in a NativeAOT program shows `Counterexample: {  }` and `Counterexample as C#: {  }`, but the JIT run shows `{ Id = 10, Name = "" }` and `new global::Order(10, "")`. The result of the property is right, but the report shows no value, and `{  }` is not a valid C# expression. The justification says "a value with no usable constructor gets no expression", but the code gives a wrong expression. Fix: make the generator emit `[DynamicDependency(PublicProperties | PublicConstructors, typeof(T))]` for each registered type, fall back to `value.ToString()` when no member is visible, and give `null` in place of a C# expression when no constructor is found.
- minor: [requirement] docs/generators.md:81 The `Gen.Create` entry does not show the real behaviour. It does not say how to add the source generator, what GCSG001 means, or that a factory with a registration and `OverrideMember` always take the reflection path. The examples of `Gen.Create` and `Gen.Factory` (line 187) also put the record before the statement, so the code fails with CS8803 when a user pastes it into `Program.cs`. Fix: put the statement first and the record after it, and add two sentences on the generator, GCSG001, and the reflection-only cases.
- minor: [requirement] docs/generators.md:1 R60 (reference pages) asks for an entry for each public generator method, but `Gen.Advanced.Error<T>` has no entry. The slice test reads only `Gen` and `Gen.Realistic`, so it does not catch the gap. Fix: add a `### Gen.Advanced.Error` entry, and make the test read the public nested classes of `Gen`.

Checked with no finding: generated and reflection values are equal for seed 0 and 100 values for a nested record, an enum, a flags enum, a nullable enum, `string?`, `int?`, `DateTime?`, a record struct, `Box<int>`, a class with a constructor, a record with an extra init property, a record in a nested class, a record in a nested namespace, and two records with the same simple name in two namespaces. A recursive type, a class with only settable properties, a collection member, and a private constructor give GCSG001 with the type name and keep the reflection path. Shrinking gives the same counterexample and shrink count on both paths, and the replay string of the generated path replays the same value on the reflection path. A record from a referenced project uses the generated path. A custom factory and a member override do not use the generated code. The trimmed and NativeAOT publish of `Order(int Id, string Name)` gives no GalaxyCheck IL warning and passes. The incremental model holds only strings and value-equal records, and the generator adds one source file with a fixed hint name, so no duplicate hint name occurs. All 66 examples of `docs/generators.md` compile on net11.0 when each record goes after the statements, and each example samples values that match its description. A constructor that throws gives a generation error on both paths. The generated path loses the member path in the message, but it keeps the inner exception.
