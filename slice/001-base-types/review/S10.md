# Review of S10 (the source generator and the reference pages), round 2

- minor: [correctness] src/GalaxyCheck.SourceGeneration/GenCreateGenerator.cs:101 GCSG002 (the call uses reflection) fires on `Gen.Create<T>(Func<GenParameters, (T, GenParameters)>)`, an overload that uses no reflection. The fix widened the candidate check from zero arguments to one argument, and `Plan` accepts any `Create` on `Gen` with one parameter. So `Gen.Create<int>(p => (p.Size.Value, p))` and `Gen.Create<Order>(p => (new Order(1, "x"), p))` get "Create<Order>() with a NullabilityInfo builds the generator by reflection", and `Gen.Create<T>(p => (v, p))` in a generic method gets "the type argument 'T' holds a type parameter". With `TreatWarningsAsErrors=true`, each of these calls breaks the build, and the message tells the user that working AOT-safe code fails in NativeAOT. Fix: in `Plan`, return null unless the one parameter has the type `System.Reflection.NullabilityInfo`, and add a slice test that `Gen.Create<T>(func)` gets no diagnostic. Status: fixed after round 2 (the check now accepts only a `NullabilityInfo` parameter); a scratch build shows no GCSG002 on the function overload.
- minor: [correctness] src/GalaxyCheck.SourceGeneration/GenCreateGenerator.cs:156 GCSG002 fires on a factory with no registration when the factory comes from a variable or a method. `var f = Gen.Factory(); f.Create<Order>()` and `MyFactory().Create<Order>()` both get "on a factory with a registration", but at run time both use the generated code, because the factory has no registration. The warning is conservative, but its text is wrong, and `docs/generators.md:48` does not say that only the direct `Gen.Factory().Create<T>()` form is free of the warning. Fix: change the reason to "on a factory that the generator cannot see is free of registrations", and add that sentence to the docs.
- minor: [correctness] src/GalaxyCheck/Runners/Assert.cs:198 The round 1 minor about the failure report (a counterexample with no readable members) is fixed only for a top-level value. A value inside a tuple still goes to `ExampleRenderer.Render`, so a counterexample `(0, new Opaque(0))` shows `[0] = 0` and `[1] = Opaque` under "Counterexample as C#", which is not a C# expression. Fix: when `CSharpExpression.TryFormat` fails for any value, write the "not available" line in place of the rendered text.
