# Review of S6 (property features), round 2

- major: [requirement] src/GalaxyCheck/Runners/Check.cs:532 The size boost on a discard makes a false health check for an ordinary precondition that keeps small values. Each discard raises the size and only a test case that runs lowers it, so the size climbs to 100 when fewer than half of the values pass. `Property.ForAll(Gen.Int32().ListOf(), xs => { Property.Precondition(xs.Count <= 1); return true; }).Check(seed: 0)` passed 100 iterations at 7a38637, and now it fails with TooManyDiscards ("1001 of 1100") for seeds 0, 1, and 2. Fix: keep the boost from driving the size away from the values that pass, for example reset the boost to 0 when a test case reaches the test function, or boost only while no test case has run. Check that this property passes and that `Precondition(x > 0)` over `Gen.Int32()` still passes.
- minor: [requirement] src/GalaxyCheck/Runners/Check.cs:510 The boost also changes a size that the user fixed with the `size` option, so a run with `size: 0` and a discard tests larger sizes. Fix: leave the size as it is when the user gives it.
- minor: [requirement] src/GalaxyCheck/Runners/Check.cs:419 The discard share is judged only at the end, so a precondition that rarely passes runs up to max(1000, 10 × iterations) discarded test cases first. With 10000 iterations and a precondition that keeps 1%, the run makes 100,001 test cases before it fails. Fix: also stop early when the share is far above 90% after enough values, for example 99% after 1000.
- minor: [architecture] src/GalaxyCheck/Runners/CSharpExpression.cs:325 The XML comment of `WriteInitializer` says that it runs no code of the type, but it calls each public getter, and the constructor path before it calls the public constructor and the getters. Fix: say in the comment that the getters run.
- minor: [requirement] src/GalaxyCheck.Xunit/Internal/PropertyAssertRunner.cs:10 R41 says that the token is cancelled when the test framework cancels the test. Without a time limit, the token is `CancellationToken.None`, and the xunit v2 runner does not link the token to the cancellation source of the test run. Fix: link the token to the cancellation source of the xunit v2 test invoker.
- minor: [requirement] src/GalaxyCheck.Xunit.Tests/IntegrationTests/__snapshots__ The output snapshots of the failing samples, for example `FallibleVoidProperty_0`, hold "Counterexample: [0]", the old replay format, and no "Counterexample as C#" line. The current message lists "Counterexample: 0". The check runs only on Windows, so the Linux run does not show the mismatch. Fix: update the snapshots to the current message.
