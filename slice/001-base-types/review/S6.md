# Review of S6 (property features), round 1

- major: [requirement] src/GalaxyCheck/Runners/Check.cs:474 An exhaustive run replays the same index after a discard, because `_iteration` does not advance on a discard. `Property.ForAll(Gen.Int32().Between(1, 10), x => { Property.Precondition(x != 5); return true; })` repeats the value 5 until the run trips `TooManyDiscards` ("96 of 100"), and the values 6 to 10 never run. Fix: keep a separate index for the exhaustive walk, and advance it on each test case, discarded or not.
- major: [requirement] src/GalaxyCheck/Runners/Check.cs:487 A discard does not advance the size, so a generator at size 0 gives its origin again and again. Ordinary preconditions trip `TestFunctionNeverRuns` after 100 discards: `Precondition(x > 0)` over `Gen.Int32()`, `Precondition(x != 0)` over `Gen.Int32().Between(0, 1000)` with `exhaustive: false`, and `Precondition(xs.Count > 3)` over a list. With both checks suppressed, the first property passes with 0 iterations and 1001 discards. Fix: grow the size with each discard, as the `Where` operator does, so that a precondition that most values meet reaches the test function.
- major: [requirement] src/GalaxyCheck/Runners/Check.cs:592 The ratio check of `TooManyDiscards` runs in the middle of the run, when 100 values have been generated. At that point the test cases have the smallest sizes. `Property.ForAll(Gen.Int32().Where(x => x > 50), x => true)` trips with "109 of 115". With the check suppressed, the full run discards 380 of 480 values (79%), so R56 (more than 90%) does not hold. Fix: judge the ratio over the whole run, at the end. Keep the early stop for a generator that cannot make a value.
- major: [requirement] src/GalaxyCheck/Gens/ParametersGen.cs:38 R55 does not hold for several of its kinds. `Gen.Byte().Between(250, 255)` (ByteGen.cs:78) and `Gen.Enum<T>()` of a flags enum (EnumGen.cs:21) are not finite. `Gen.Create<bool>()`, `Gen.Create<MyEnum>()`, `Gen.Create<(bool, MyEnum)>()`, and `ParametersGen` are not finite either, so `Property.Reflect` and each `[Property]` method with a `bool` and an enum parameter run 100 times, and `PropertyAttribute.Exhaustive` has no effect. Fix: implement `IFiniteGen` for these generators. The parameters generator is the product of its parameter generators, and it leaves out the token.
- major: [requirement] src/GalaxyCheck.Xunit/Internal/PropertyInitializer.cs:33 The runner does not read `SuppressHealthCheckAttribute`, and `PropertyRunParameters` has no field for it. A `[Property]` test cannot suppress a check by name (R56 and interface.md). Fix: read the attribute from the method and the class, and pass `suppressHealthChecks` to `AssertAsync`.
- major: [requirement] src/GalaxyCheck/Runners/CSharpExpression.cs:177 Some values of the kinds that R39 lists get no expression, and the report falls back to the old text. These are the base types `Half`, `nint`, and `nuint`; a class with a public parameterless constructor and settable properties (`new Settable { A = 1, B = "q" }`); and a struct with public settable fields or properties. Fix: add cases for the three base types, for example `(global::System.Half)1.5` or `BitConverter.UInt16BitsToHalf(...)`, `(nint)(-5)`, and `(nuint)5`. Add an object-initializer path (`new T { P = ... }`) for a type with a public parameterless constructor whose readable members are settable.
- major: [requirement] src/GalaxyCheck/Runners/CSharpExpression.cs:139 A `ValueTuple<int>` with 1 element gives `(5)`, and that expression is the int 5, not the tuple. `Gen.ValueTuple(gen1)` makes such values. Fix: write `new global::System.ValueTuple<T1>(...)` when the tuple has 1 element.
- major: [requirement] src/GalaxyCheck/Runners/CSharpExpression.cs:384 `TypeName` loses the nested part of a type that is declared in a generic type. The enum `Outer<int>.Inner.Y` gives `global::Probe.Outer<int>.Y`, and the record `Outer<int>.R(3)` gives `new global::Probe.Outer<int>(3)`. Neither compiles. A type name that is a keyword, for example `@class`, gives `global::Probe.class`, which does not compile. Fix: build the name from each declaring type, give each level its own generic arguments, and prefix each keyword segment with `@`. Return false when the name cannot be built.
- minor: [requirement] src/GalaxyCheck/Runners/Check.cs:192 With `TooManyDiscards` suppressed, a generator whose `Where` gives up still fails the property with a raw `GenExhaustionException`, and its message is "Exception of type 'GalaxyCheck.Exceptions+GenExhaustionException' was thrown". Fix: give the old exhaustion message, or a message that says the generator could not make a value.
- minor: [requirement] src/GalaxyCheck/Runners/CheckResult.cs:125 The exhaustive line says that "each of the N possible inputs ran one time", with N as the count of iterations. A discarded test case does not count as an iteration, so N is not the count of inputs when a test case is discarded. Fix: use the count of the domain.
- minor: [architecture] src/GalaxyCheck/Runners/CSharpExpression.cs:337 `Rebuilds` calls a public constructor of the user's type while it formats the report. The constructor can have side effects or be slow. Fix: compare the members without running user code where you can, or state this behaviour in the XML comment.
- minor: [requirement] src/GalaxyCheck.Xunit/Internal/PropertyAssertRunner.cs:10 R41 says that the token is cancelled when the test framework cancels the test. Without a time limit, the token is `CancellationToken.None`, and the xunit v2 runner does not link the token to the cancellation of the test run. Fix: link the token to the cancellation source of the xunit v2 test invoker.
