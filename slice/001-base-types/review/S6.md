# Review of S6 (property features), round 4

- major: [requirement] src/GalaxyCheck/Operators/Where.cs:41 One value that a filter discards 100 times in a row fails the run with TooManyDiscards ("could not make a value"), although the run discards less than 90% of its values. The sweep spreads the retries over all 101 sizes, so a filter that keeps values only at large sizes, and that has no good size yet, keeps about one retry in 20. `Gen.Int32().Between(0, 50).SelectMany(n => Gen.Int32().Between(0, 100).Where(x => x > n && x < n + 30))` with `exhaustive: false` fails for 16 of the seeds 0 to 199 (the first is seed 9), and its passing runs discard 77% to 86%. At 7f6f2a5 it passed for each of the 200 seeds, so the fix caused this. `Gen.Int32().Between(0, 100).Where(x => x > 20 && x < 40).ListOf()` fails the same way for seeds 30, 106, 121, 169, and 173. Fix: let the retries of one value go over more than one sweep, or judge an exhausted value by the share of the run that R56 states. Check that both generators pass for seeds 0 to 199, and that the 5% filter with no bias and `Where(x => false)` still fail.
- major: [requirement] src/GalaxyCheck/Gens/Parameters/GenSource.cs:100 The good size of a filter is keyed by the filter object, and `SelectMany` builds a new filter object for each value. So a filter inside `SelectMany` never uses a learned size, and each value starts the sweep again. `Gen.Int32().Between(0, 10).SelectMany(n => Gen.Int32().Between(0, 100).Where(x => x > 20 && x < 40))` with `exhaustive: false` fails with "the run discarded ... more than 90%" for 131 of the seeds 0 to 199. The same filter outside `SelectMany` passes for each seed, and keeps up to 23% of the values at its best size. The fix did not cause this: the property failed for each seed at 7f6f2a5. The dictionary also keeps each filter object and its closure until the run ends. Fix: key the good size by a value that each object of the same filter shares, for example the method of the predicate, or the order of the filter in the test case. Check that the property passes for seeds 0 to 199.
- minor: [architecture] src/GalaxyCheck/Runners/CSharpExpression.cs:325 The XML comment of `WriteInitializer` says that it runs no code of the type, but it calls each public getter, and the constructor path before it calls the public constructor and the getters. Fix: say in the comment that the getters run.
- minor: [requirement] src/GalaxyCheck.Xunit/Internal/PropertyAssertRunner.cs:10 R41 says that the token is cancelled when the test framework cancels the test. Without a time limit, the token is `CancellationToken.None`, and the xunit v2 runner does not link the token to the cancellation source of the test run. Fix: link the token to the cancellation source of the xunit v2 test invoker.
- minor: [requirement] src/GalaxyCheck.Xunit.Tests/IntegrationTests/__snapshots__ The output snapshots of the failing samples, for example `FallibleVoidProperty_0`, hold "Counterexample: [0]", the old replay format, and no "Counterexample as C#" line. The current message lists "Counterexample: 0". The check runs only on Windows, so the Linux run does not show the mismatch. Fix: update the snapshots to the current message.
