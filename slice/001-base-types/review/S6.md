# Review of S6 (property features), round 3

- major: [requirement] src/GalaxyCheck/Runners/Check.cs:511 The size cycle on a discard makes a false health check for an ordinary mid-range precondition. Each discard moves the size one step round the whole cycle 0 to 100, so the run spends most of its test cases at sizes where no value passes. `Property.ForAll(Gen.Int32().Between(0, 100), x => { Property.Precondition(x > 20 && x < 40); return true; }).Check(seed: s, exhaustive: false)` passed for 6 of the seeds 0 to 9 at 3bed7fa, and now passes for 1 of them; the others fail with TooManyDiscards, for example "1001 of 1081" for seed 0. The fix caused this. The round 2 cases now pass: `xs.Count <= 1` and `xs.Count > 3` over a list of ints, and `x > 0` over `Gen.Int32()`. Fix: keep the run near the sizes where values pass, for example search outward from the size of the last test case that passed (+1, -1, +2, -2, and so on) instead of a full cycle. Check that the mid-range precondition and the three round 2 cases pass for seeds 0 to 9.
- major: [requirement] src/GalaxyCheck/Runners/Check.cs:622 The TooManyDiscards check fails on ordinary `Where` filters. For seeds 0 to 9, `Gen.Int32().ListOf().Where(xs => xs.Count > 3)` fails on each seed ("999 of 1099" for seed 0), `Gen.Int32().Between(0, 100).Where(x => x > 20 && x < 40)` with `exhaustive: false` fails on each seed ("2269 of 2369"), and `Gen.Int32().ListOf().Where(xs => xs.Count <= 1)` fails on 3 seeds. The same preconditions discard far fewer values, for example about 160 of 260 for `xs.Count > 3`. The fix did not cause this: the results are the same at 3bed7fa, and these filters also failed at 7a38637. Fix: let a value that a `Where` filter drops lead the run to sizes where the filter keeps values, as a precondition discard does, or judge the filter by the values it keeps. Check that the three filters pass for seeds 0 to 9 and that a filter that keeps about 5% still fails.
- minor: [architecture] src/GalaxyCheck/Runners/CSharpExpression.cs:325 The XML comment of `WriteInitializer` says that it runs no code of the type, but it calls each public getter, and the constructor path before it calls the public constructor and the getters. Fix: say in the comment that the getters run.
- minor: [requirement] src/GalaxyCheck.Xunit/Internal/PropertyAssertRunner.cs:10 R41 says that the token is cancelled when the test framework cancels the test. Without a time limit, the token is `CancellationToken.None`, and the xunit v2 runner does not link the token to the cancellation source of the test run. Fix: link the token to the cancellation source of the xunit v2 test invoker.
