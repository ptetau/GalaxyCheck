# Review of the tests of S7 (stateful testing), round 3

- minor: [tests] test_001_S7_R43_decrement_that_throws_an_expected_exception_passes_and_advances_the_model A runner that ends the run as a pass at the first expected exception also passes the test, because then no later postcondition checks the model. Fix: check that a command after the expected exception ran, or give the command a postcondition that compares the system with the model after it.
- minor: [tests] test_001_S7_R43_correct_counter_passes_100_sequences_each_with_new_system_and_model The new-model check counts each call of `newModel`, and the generator calls it too. The model is an `int`, so a model that leaks from one run into the next cannot show. Fix: use a model that is a record with a run ID, or count only the calls of `newModel` from the runner.
- minor: [tests] test_001_S7_R43_increment_that_adds_two_at_three_fails_by_a_postcondition The test checks only `<- failed`. A failure that comes from a different cause also passes. Fix: check that the message names a postcondition as the cause.
- minor: [tests] test_001_S7_R44_failure_shrinks_to_four_increments No test checks that the inputs of each remaining command shrink (R44). This line of R44 has no acceptance line. Fix: add a test with a command whose generated input causes the failure, and check that the input shrinks to the smallest value that fails.
- minor: [tests] test_001_S7_R42_no_decrement_at_model_zero_in_1000_sequences The test class is named `S9_StatefulTests`, but the tests are for S7. Fix: rename it `S7_StatefulTests`.
