# Review of the tests of S7 (stateful testing), round 1

- major: [tests] test_001_S7_R42_no_decrement_at_model_zero_in_1000_sequences The `nextCommand` of the test offers "decrement" only when the model is above 0. The test then never calls the precondition filter of the generator. A generator that never calls `Precondition` passes the test. Fix: make `nextCommand` offer "increment" and "decrement" at each model, so that only the precondition keeps "decrement" away from model 0.
- major: [tests] test_001_S7_R44_each_precondition_holds_in_each_shrunk_sequence_that_runs This test uses the same `nextCommand`, which offers "decrement" only above model 0. A shrinker that deletes commands and never checks the precondition at the new positions passes the test. Fix: use a `nextCommand` that offers "decrement" at each model. Use a failure whose first counterexample holds "increment" and "decrement" commands, so that the shrinker deletes commands in front of a "decrement".
- major: [tests] test_001_S7_R43_decrement_that_throws_an_unexpected_exception_fails A runner that fails on each exception, expected or not, passes the test. R43 and the machine StatefulRun (T3) say that only an exception that the command does not expect fails. Fix: add a test with a command whose `Expects` returns true for the exception it throws. Check that the property passes and that the model advanced as `NextModel` defines.
- major: [tests] test_001_S7_R45_report_lists_four_commands_in_order_and_names_the_fourth_as_failed The `ToString()` of each command equals its class name, and no command has an input. A report that writes the type name of each command, and not its `ToString()` with its inputs, passes the test. Fix: give the counter commands an input, for example "increment by n", and a `ToString()` that differs from the class name and holds the input. Check that each line holds that text.
- minor: [tests] test_001_S7_R43_correct_counter_passes_100_sequences_each_with_new_system_and_model The new-model check counts each call of `newModel`, and the generator calls it too. The model is an `int`, so a model that leaks from one run into the next cannot show. Fix: use a model that is a record with a run ID, or count only the calls of `newModel` from the runner.
- minor: [tests] test_001_S7_R43_increment_that_adds_two_at_three_fails_by_a_postcondition The test checks only `<- failed`. A failure that comes from a different cause also passes. Fix: check that the message names a postcondition as the cause.
- minor: [tests] test_001_S7_R44_failure_shrinks_to_four_increments No test checks that the inputs of each remaining command shrink (R44). This line of R44 has no acceptance line. Fix: add a test with a command whose generated input causes the failure, and check that the input shrinks to the smallest value that fails.
- minor: [tests] test_001_S7_R42_no_decrement_at_model_zero_in_1000_sequences The test class is named `S9_StatefulTests`, but the tests are for S7. Fix: rename it `S7_StatefulTests`.
