# Review of the tests of S3 (number generators), round 1

- major: [tests] test_001_S3_R2_uint32_between_10_and_20_stays_in_bounds_and_hits_both The acceptance line names `Gen.UInt32().Between(10, 20)`, but the test sets the two bounds with `GreaterThanEqual` and `LessThanEqual`. A wrong version passes whose `Between` extension for `uint` is wired wrongly, for example one that ignores a bound, swaps them, or treats the upper bound as exclusive. Fix: call `Between(10, 20)`.
- major: [tests] test_001_S3_R3_sbyte_between_minus_50_and_minus_10_always_failing_shrinks_to_minus_10 The acceptance line names `Gen.SByte().Between(-50, -10)`, but the test sets the two bounds with `GreaterThanEqual` and `LessThanEqual`. No test calls `Between` for `sbyte`, so a wrong `Between` for `sbyte` passes. Fix: call `Between(-50, -10)`.
- minor: [tests] test_001_S3_R9_single_always_failing_shrinks_to_zero The test compares the counterexample with `0f` through `Equals`, which also accepts negative zero. A wrong version that shrinks to -0 passes. Fix: also assert that the counterexample is not negative zero.
- minor: [tests] test_001_S3_R1_sbyte_covers_full_range The R1 (integers) tests and the integer R2 and R3 tests all fix the size at 100, and the acceptance lines name no size. A wrong version that reaches the minimum and the maximum only at the largest size passes. Fix: sample with the default size, as the real number tests do.
- minor: [tests] test_001_S3_R5_half_has_fraction_negative_positive The class of S3_RealTests.cs is named `S4_RealTests`, which names the wrong slice. Fix: rename the class to `S3_RealTests`.
