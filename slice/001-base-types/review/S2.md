# Review of S2 (a core that is 100 times faster), round 1

- minor: [requirement] README.md:13 R51 (documented API stays) says that each block compiles "with no change", but the blocks of commit 2618845 never compiled. `IGen<Test>` does not resolve with `using GalaxyCheck;`, `Property.ForThese` and `IReadOnlyList.Sort()` do not exist, and six blocks were members with no class. The new core did not break the documented API: each rewritten block uses only `Property.ForAll`, `ForAll`, and LINQ members that existed at 2618845. Fix: record this as a decision in spec.md, so that R51 reads "compiles against the current library" for blocks that were already wrong.
- minor: [architecture] src/GalaxyCheck/Runners/Replaying/ReplayEncoding.cs:51 The decoder allocates the choice array (up to 8 MB) before it checks that the bytes hold that many choices. For example, the 8-character string `AgAA//8/` allocates 8 MB and then fails. Fix: reject a length above the count of the remaining bytes before the allocation.
- minor: [architecture] src/GalaxyCheck/Runners/Replaying/ReplayEncoding.cs:45 The decoder truncates a seed above `uint.MaxValue` and accepts the string. Fix: reject a seed varint above `uint.MaxValue`.
- minor: [requirement] src/GalaxyCheck.Benchmarks/PerformanceGate.cs:91 The gate passes a report with no cases, or with a case of R46 (benchmark suite) missing. Fix: fail and name each case of R46 that the report does not hold.
- minor: [architecture] src/GalaxyCheck/Runners/Shrinker.cs:162 The binary search cannot shrink a value inside `Where`. A rejected middle value makes the filter draw again, so the choices get longer and the candidate is never simpler. For example, a list of `Where(x => x % 3 == 0)` values with "sum below 200" stops at `[42,36,33,45,45]`, not at one element. The old core was not minimal either, so this is no regression. Fix: in the binary search, also try only the candidates whose values pass the filter, or let a span shrink to its own simplest passing value.
- minor: [architecture] src/GalaxyCheck/Gens/Internal/BaseGen.cs:27 The mutable `_cache` field is part of the record equality of `GenProvider<T>`. Two generators with the same configuration compare unequal after one of them is used. Fix: exclude the cache from equality, or keep it outside the record.
- minor: [architecture] src/GalaxyCheck/Operators/Unfold.cs The slice deletes the public `IGen<T>.Unfold` operator (custom shrinking) and gives no replacement. D12 (performance limits) allows this for the advanced API, and README does not use it. Fix: list the removed operator in docs/deprecated-features.md.
