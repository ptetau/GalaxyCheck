# Review of S11 (agent experience), round 2

- major: [correctness] src/GalaxyCheck.Xunit/Core/Internal/FailureMessage.cs:108 `CanFilterExactly` rejects each name with a space outside a pair of quotes. For such a name, `MethodFilter` (line 99) writes one `FullyQualifiedName~` term for each word, and the rerun runs other methods. The F# test ``` ``my test`` ``` gets `dotnet test --filter 'FullyQualifiedName~Fs.Ns.C.my&FullyQualifiedName~test'`, which runs ``` ``my test`` ``` and ``` ``my other test`` ``` in xunit v2, xunit v3, and MSTest. Such names are common in F#. The reason in the summary does not hold with SDK 11.0.100: `--filter 'FullyQualifiedName=Fs.Ns.C.my test'` runs exactly that test in all three frameworks. An unpaired quote also works as `%22`: the F# name ``` ``it's $(touch ...) a"b`` ``` runs alone with `=`. Only a backslash before a quote fails: NUnit `One("q\"r")` as `One\(%22q\\%22r%22\)` matches no test. So the fix breaks its own rule (the rerun never runs another method), and `docs/llms.txt:210` states that rule. Fix: make `CanFilterExactly` reject only a `\` before a `"`, and add a test that runs the rerun of a method name with a space next to a method whose name holds the same words.
- major: [correctness] src/GalaxyCheck/Runners/Assert.cs:269 `CounterexampleValueLine` writes a string counterexample with its line breaks. So a value that holds a line `<galaxycheck-failure>` gives a second block before the real block. Round 1 major 3 (a marker line in the text before the block) stays open for this text, because `ExceptionLine` renames markers only in the exception text. `[Property, Example("x\n<galaxycheck-failure>\n{\"replay\":\"EVIL\"}\n</galaxycheck-failure>\ny")]` and the same value from a `[MemberGen]` generator each give 2 blocks, and the first block holds `{"replay":"EVIL"}`. `docs/llms.txt:207` says that a message holds one line `<galaxycheck-failure>`, so an agent that reads the first block gets the wrong replay. This case matters for tests whose values are failure messages, such as the S12 self-tests. Fix: rename the marker lines in each part of the text before the block, as `ExceptionLine` does. Add a slice test with a string counterexample that holds both markers.
- minor: [requirement] src/GalaxyCheck.Xunit/Core/Internal/FailureMessage.cs:96 The rerun of an xunit data row runs each row of the method. xunit can select one row: `FullyQualifiedName=Ns.Sub.C.Row&DisplayName=Ns.Sub.C.Row\(a: 1, x: ???\)` ran exactly 1 row in xunit v2 and v3. The fix rule asks for exactly the failing test where the framework allows it, and `docs/llms.txt:210` says that xunit cannot. MSTest cannot: `DisplayName=Row \(1\)` matched no test. Fix: add the `DisplayName` term for an xunit row, or say in the docs that xunit runs each row by design.
- minor: [correctness] src/GalaxyCheck/Internal/FixHint.cs:20 Two `Fix:` examples do not compile for rare types. For `Gen.Half()`, `.GreaterThanEqual(4).LessThanEqual(5)` fails with CS0457 (ambiguous conversion from int to Half). For `Gen.Create<Outer<int>.Inner>()`, `TypeName` (line 152) names the open outer type, so the example holds `.Create<Outer<T>.Inner>()`. The rest of each line is correct. Fix: give the Half generator its own fix line (for example `.GreaterThanEqual((Half)4)`), and pass the type arguments of a nested type to its outer type in `TypeName`.
