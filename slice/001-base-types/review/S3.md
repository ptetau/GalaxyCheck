# Review of S3 (number generators), round 1

- major: [requirement] src/GalaxyCheck/Gens/RealGens.cs:183 The decimal generator crashes for valid options. The move from the origin toward a bound overflows in decimal arithmetic, and the run fails with the generic "Exception thrown" error that wraps an `OverflowException`. For example, `Gen.Decimal().Between(decimal.MinValue, decimal.MinValue + 1)` fails on 1 of 50 seeds, and `Gen.Decimal().ShrinkTowards(decimal.MaxValue)` fails on 6 of 50 seeds (100 values for each seed). Fix: compute the move in a form that cannot overflow, or catch the overflow and use the bound. Then clamp to the bounds.
- major: [requirement] src/GalaxyCheck/Gens/RealGens.cs:160 R9 (float shrinking): a special value does not shrink to a simpler finite value that fails. A special value is the exponent slot after the largest exponent, and its mantissa is only the index of the special value. So a lower exponent gives a tiny value that passes, and the shrinker stops at the special value. Measured on 10 seeds: `Gen.Double()` with "fails when the value is above 1e300" gives `double.MaxValue` on 10 seeds. "Fails when the value is below -3.5" gives `double.MinValue` on 1 seed, not -4. `Gen.Double().Between(-10, -2)` with "fails when the value is at most -5" gives -10 (the bound, which is a special value) on 6 seeds, not -5. Fix: let each special value shrink to its own finite encoding. For example, add a shrink candidate that replaces the special choice by the choices of the same finite value (for `MaxValue`, the largest exponent and mantissa; for a bound, the whole number or the mantissa that gives the bound), so that the normal shrink passes can then lower it.
- major: [requirement] src/GalaxyCheck/Gens/RealGens.cs:149 R5 (binary floats): the distribution almost never gives a value with a fraction near one. The mantissa is drawn over its full width, so the "near" exponents give values near 1e15, not near one, against the comment at line 70. Measured on 2000 values of `Gen.Double()`: 59 values are from 1e-3 to 1e3 in magnitude, and 7 of them have a fraction part. The property "fails when the value is between 1 and 2" is not falsified on any of 10 seeds with 100 iterations. With a bound the values collapse to the bound: `Gen.Double().GreaterThanEqual(1000)` gives exactly 1000 for 54% of values and a whole number for 92%, and `Gen.Double().Between(1e6, 2e6)` gives exactly 1e6 for about half. Fix: draw the mantissa with a width that grows with the size (as the whole numbers do with `IntCore.Limit`), or center the near exponents on minus the precision, so that a value near one with a fraction part is common. Keep the full-width draws for the full range.
- major: [requirement] src/GalaxyCheck/Gens/IntegerGens.cs:220 R2 (integer options): `GreaterThan` above the maximum of the type, and `LessThan` below the minimum (line 233), give a generator error with the message "Arithmetic operation resulted in an overflow.", which names no option. For example, `Gen.UInt64().GreaterThan(ulong.MaxValue)` and `Gen.UInt128().LessThan(0)`. Fix: give a message that names the option, for example "'minExclusive' must be below the maximum of the type".
- minor: [requirement] src/GalaxyCheck/Gens/RealGens.cs:174 With a bound or an origin of a large magnitude, the shifted value rounds to the origin. `Gen.Double().GreaterThanEqual(1e308)` gives 3 different values in 1000, `Gen.Single().GreaterThanEqual(1e38f)` gives 19, and `Gen.Double().ShrinkTowards(double.MaxValue)` gives 12. Fix: scale the drawn value to the width of the range when the range is wide compared with its distance from zero, or use the move toward a bound for these values.
- minor: [requirement] src/GalaxyCheck/Gens/Internal/RealFormat.cs:134 R10 (decimal): a finite decimal is at most `ulong.MaxValue` times 10^9, about 1.8e28. The values from 1.8e28 to 7.9e28 appear only as `decimal.MinValue` and `decimal.MaxValue`. Fix: draw a 96-bit mantissa, or allow the exponent 10 with a mantissa limit.
- minor: [requirement] src/GalaxyCheck/Gens/RealGens.cs:96 An infinite bound is accepted and clamped to the finite range. `Gen.Double().GreaterThanEqual(double.PositiveInfinity)` gives only `double.MaxValue`, with no error. Fix: give a generator error that names the option, as for a NaN bound, or document the clamp.
- minor: [architecture] src/GalaxyCheck/Gens/RealGens.cs:174 For `Half`, the shift from the origin and the move toward a bound (line 183) use `Half` arithmetic, not double. The design builds `Half` in double so that the values are the same on net10.0 and net11.0 (R20, same values on both targets). Fix: do these two steps in double for a type narrower than double, as `BinaryRealFormat` does.
