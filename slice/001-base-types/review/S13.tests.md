# Test review of S13 (The reference suite), round 1

- major: [tests] test_001_S13_R68_generator_laws_hold_on_seeds_0_to_19 The table of generators misses public generators of this spec: `Gen.Element` (its bias changed in this slice), `Gen.Enum<T>()`, the net11.0 generators of R18 (`Gen.Decimal32()`, `Gen.Decimal64()`, `Gen.Decimal128()`, `Gen.BFloat16()`, `Gen.ComplexOf`), and the R31 collections through `Gen.Create<T>()`. A version where the shrink of an element choice does not end, or where its replay gives another value, passes. Fix: add rows for each of them, the net11.0 rows under a net11.0 condition.
- major: [tests] test_001_S13_R74_random_compositions_never_crash_or_hang_and_each_failure_shrinks_and_replays The test counts each `GenErrorException` as a reported error and not as a crash. The library also reports an exception that a generator throws (for example an index out of range in the engine) as a generation error that says "Exception thrown". So a version that crashes inside a generator during generation or during a shrink passes. Fix: accept only the TooManyDiscards health check, fail on any other `GenErrorException`, and fail when more than a small share of the 200 programs give a reported error.
- major: [tests] test_001_S13_R74_random_compositions_never_crash_or_hang_and_each_failure_shrinks_and_replays The "choice" of the compositions is `Gen.Element` of two generators followed by `SelectMany`, which is a bind. The library's own choice generator (`Gen.Choose<T>().WithChoice(gen, weight)`) and `Gen.Recursive` never appear, and this slice changed both (a span for each branch). A version whose weighted choice records a wrong span, so that a shrink crashes or does not replay, passes. Fix: build the choice case with `Gen.Choose<T>().WithChoice` and add a case with `Gen.Recursive`.
- minor: [tests] test_001_S13_R68_generator_laws_hold_on_seeds_0_to_19 Law 3 removes the consecutive repeats of the failing inputs before it looks for a repeat. The test function no longer runs on a candidate that is not simpler, so a consecutive repeat is now an accepted shrink that gives the same value again. A shrinker that accepts the same value twice in a row passes. Fix: look for repeats in the failing inputs after the first one, without the collapse, or collapse only the first failing value and its first re-run.
- minor: [tests] test_001_S13_R72_replay_of_a_property_with_another_generator_is_no_longer_valid The check for the word "valid" also matches "invalid", so a version that rejects the replay as a malformed string (and not as a replay that is no longer valid) passes. Fix: look for "no longer valid".
- minor: [tests] test_001_S13_R71_each_new_integer_generator_gives_its_minimum_and_maximum_in_2000_values The test and its partner for the existing integers sample at the fixed size 100. R71 names no size, so a generator that gives its extremes only at the largest size passes. Fix: sample with the default sizes of `Sample`, or state why size 100 is the case that R71 means.
- minor: [tests] test_001_S13_R71_boolean_passes_chi_squared The chi-squared check only has an upper limit, so a generator that alternates true and false (statistic 0) passes, and so does a round-robin element choice. Fix (optional): also check that no value repeats a fixed cycle, for example that the sequence is not periodic with period 2 or 10.
- minor: [tests] test_001_S13_R75_two_runs_in_two_processes_give_the_same_text The property of the sample has no filter, bind, or choice, so state that differs between processes in those paths (for example a key that depends on a hash) is not tested. Fix: add a filter and a bind to the generator of the sample and of the two in-process tests.
