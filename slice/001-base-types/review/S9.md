# Review of S9 (the NUnit and MSTest packages, failure memory, explicit examples), round 2

- major: [correctness] src/GalaxyCheck.Xunit/Core/Internal/PropertyAssertRunner.cs:66 A stale saved replay can now fail a test that holds on every run. The catch takes only `GenErrorException`, and any other error of the saved replay leaves the entry in the file. In an NUnit scratch project, `Filtered([MemberGen] int x)` with the generator `Gen.Int32().Where(x => x > 2_000_000_000)` passed with no entry. With the saved entry of a plain `int` test, it failed with "Health check TooManyDiscards failed" in two runs out of two, and the entry stayed. The message does not name the saved failure, so the user has no hint to delete it. Round 1 failed such a test only one time. Fix: treat each error of the saved replay except `PropertyFailedException` as a stale replay: remove the entry and go on with the examples and the generated run, which report a real generator error with its own message.
- major: [requirement] src/GalaxyCheck.TUnit/Internal/Infrastructure/TUnit/TestExecutors.cs:77 R38 (failure memory) does not hold for a TUnit class with a `[ClassDataSource]` object whose text changes between runs. The key now holds the C# form of each class argument, and `FailureFile.Arguments` (src/GalaxyCheck.Xunit/Core/Internal/FailureMemory.cs:71) formats a record with all its values. In a TUnit scratch run, `WithDb(Db db)`, with the record `Db("port=<random>")`, saved the key `Tu.WithDb(new global::Tu.Db("port=898837073")).Fails` and then `Tu.WithDb(new global::Tu.Db("port=1417526605")).Fails`. So the second run did not replay the saved failure, and the file grows by one entry on each run. A record with a container address or a temporary path is the usual form of such an object. Fix: in the TUnit key, use only the arguments of `[Arguments]` (constant values), or the index of the class data row, and not the values of an injected object.
- major: [requirement] src/GalaxyCheck.Xunit/Core/Internal/PropertyExamples.cs:92 R52 (explicit examples) does not hold for an example in the full form on a row test. The loop skips each input for a row parameter, with no type check and no message. In NUnit, `[TestCase(1), Example("zz", 4)]` on `(int x, int y)` passed, but R52 asks for one failed test that names the parameter. `[TestCase(1), Example(3, 4)]` on the property "x is not 3" passed, so the pinned input 3 never ran and the user gets a false pass. Fix: on a test with rows, accept only the free form (one input for each parameter after the row), and fail the full form with a message that names the first row parameter. Or convert each row-part input with `TryConvert`, and fail with a message that names the parameter when the input differs from the row value.
- minor: [correctness] src/GalaxyCheck.Xunit/Core/Internal/FailureMemory.cs:142 With `GenerateAssemblyInfo=false`, or with a ProjectReference to the package, the build writes no `GalaxyCheck.ProjectFolder` metadata. Under `UseArtifactsOutput`, a TUnit scratch project then saved no failure. The note says "reference a GalaxyCheck package with its build files", but the project does reference it. The fix also removed the fallback to the nearest project file, so a project whose `AssemblyName` differs from its file name now loses the memory in the default layout too. Fix: name `GenerateAssemblyInfo=false` and the assembly name in the note, or write the metadata from a generated source file that does not depend on `GenerateAssemblyInfo`.
- minor: [correctness] src/GalaxyCheck.NUnit/Internal/Infrastructure/NUnit/Commands.cs:84 (still open from round 1) A false `Assume.That`, `Assert.Pass`, and the MSTest `Assert.Inconclusive` fail the property, and `Assert.Warn` is lost. Fix: treat inconclusive as a discard and `SuccessException` as a pass, and copy the warnings.
- minor: [correctness] src/GalaxyCheck.Xunit/Core/Internal/FailureMemory.cs:263 (still open from round 1) A corrupt or too large failure file turns the failure memory off with no message, and no run repairs it. Fix: warn one time and replace the file, and remove stale entries or document the limit.
- minor: [architecture] src/GalaxyCheck.MSTest/Internal/Infrastructure/MSTest/MSTestAdapter.cs:160 (still open from round 1) MSTest builds the class and runs `[TestInitialize]` for each test case and each shrink, and `[Timeout]` limits each case. Fix: document the per-case lifetime and timeout, or apply the timeout to the whole property.
- minor: [correctness] src/GalaxyCheck.NUnit/Internal/Infrastructure/NUnit/Commands.cs:64 (partly open from round 1) The row conversion message is fixed, but `AcceptPartialRows` still makes each not-runnable row with arguments runnable, whatever NUnit's reason was. Fix: clear only the reasons of too few arguments and of a return value.

Checked with no finding: round 1 major 2 (failure memory key) is fixed at its cause for NUnit and for TUnit `[Arguments]`: the fixtures `[TestFixture(5)]` and `[TestFixture(1000000)]` save the keys `Nm.Fx(5).Below` and `Nm.Fx(1000000).Below`, and each replays its own counterexample, 5 and 1000000. Round 1 major 3 (project folder lookup) is fixed at its cause: a package build records `$(MSBuildProjectDirectory)`, and an NUnit project with `UseArtifactsOutput` wrote `Proj/.galaxycheck/failures.json` next to its project file. The walk no longer falls back to another project. Round 1 major 1 (stale saved replay) is fixed for a replay that does not decode or does not fit: `HoldsNow(string s)` with an `int` entry, `Garbage(int x)` with "notareplay", `Two(int x, int y)` with an `int` entry, and `Pre(int x)` whose precondition discards the saved input each passed on the first run and lost the entry. A real `[MemberGen]` error still fails with its own message. The key of a plain test is unchanged in NUnit and TUnit (`Nm.Plain.Fails`, `Tu.Plain.Fails`). Class and row strings with dots, brackets, quotes and parentheses, and null, give distinct keys in C# literal form. The packs of GalaxyCheck.Xunit, GalaxyCheck.Xunit.V3, GalaxyCheck.NUnit, GalaxyCheck.MSTest and GalaxyCheck.TUnit each hold `buildTransitive/<PackageId>.props`. A data-row value wins over an `[Example]` value in the free and the full form, and a row value of the wrong type fails with a message that names the parameter.
