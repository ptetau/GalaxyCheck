# Review of S9 (the NUnit and MSTest packages, failure memory, explicit examples), round 1

- major: [correctness] src/GalaxyCheck.Xunit/Core/Internal/PropertyAssertRunner.cs:67 A saved replay that does not decode fails a test that holds. The catch turns each exception except `PropertyFailedException` into a `SavedFailureException`. An entry goes stale when the user changes the parameters of a test, or upgrades GalaxyCheck. In an NUnit scratch project, `HoldsNow(string s)` with the saved entry of an `int` test failed with "The saved failure of 'Nm.Fx.HoldsNow' ... did not run". `Garbage(int x)` with the entry "notareplay" failed the same way. Each test passed only on the next run. The same catch hides a real `[MemberGen]` or generator error behind the text "the saved failure did not run". Fix: when the saved replay throws an error of replay decoding (the `GenErrorException` of the replay), remove the entry and go on with the examples and the generated run. Let any other error fail the test with its own message.
- major: [requirement] src/GalaxyCheck.Xunit/Core/Internal/FailureMemory.cs:59 R38 (failure memory) does not hold for a parameterized NUnit fixture. `FullTestName` uses only the class type, the method, and the method arguments, so `[TestFixture(5)]` and `[TestFixture(1000000)]` share the key "Nf.Fx.Below". NUnit names the tests "Nf.Fx(5).Below" and "Nf.Fx(1000000).Below". In a scratch run, the fixture with limit 5 replayed the entry of the other fixture and reported the counterexample 1000000, not the shrunk 5. In the other order, a fixture that holds for the saved input removes the entry, and the failure memory is lost. A TUnit class with constructor arguments has the same fault. Fix: take the key from the name that the framework gives the test (NUnit `Test.FullName`, the TUnit test id, the MSTest full name), or add the constructor arguments of the class to the key.
- major: [requirement] src/GalaxyCheck.Xunit/Core/Internal/FailureMemory.cs:112 R38 (failure memory) does not hold for a project with `<UseArtifactsOutput>true</UseArtifactsOutput>`. `FindProjectFolder` walks up from the assembly in `artifacts/bin/<project>/debug`, and no folder above it holds the project file. So a failing NUnit test in a scratch project of this layout wrote no `.galaxycheck/failures.json`, and the test showed no sign of the lost memory. When some folder above the output holds another project file, the fallback at line 157 writes the memory into that other project. Fix: record `$(MSBuildProjectDirectory)` at build time, for example as an `AssemblyMetadata` attribute from a `buildTransitive` props file of each package, and read it in `ProjectFolder`. Keep the walk only as a fallback for the project file of the assembly itself.
- minor: [correctness] src/GalaxyCheck.Xunit/Core/Internal/PropertyExamples.cs:86 An `[Example]` replaces the values of a data row. With `[TestCase(1)]` and `[Example(3, 4)]`, the NUnit test "RowAndExample(1)" ran its first case with the inputs (3, 4). The MSTest `[DataRow(1)]` gives the same result. An example that gives only the generated parameters fails with "parameter 'x' has no input". So no example form fits a test with rows, and a row test can fail on an input that the row does not give. Fix: when the test has row arguments, take the inputs of an example only for the parameters after the row, and keep the constants of `WithDataRow` for the rest.
- minor: [correctness] src/GalaxyCheck.NUnit/Internal/Infrastructure/NUnit/Commands.cs:84 A signal of the framework in the test function becomes a counterexample. In NUnit, `Assume.That` that is false fails the property with "Falsified after 73 tests", and `Assert.Pass` fails it after 1 test. `Assert.Warn` is lost, and the test passes with no warning. In MSTest, `Assert.Inconclusive` fails the property (src/GalaxyCheck.MSTest/Internal/Infrastructure/MSTest/MSTestAdapter.cs:168). An NUnit user expects `Assume.That` to discard a case, as `Property.Precondition` does. Fix: treat `InconclusiveException` (NUnit) and the inconclusive outcome (MSTest) as a discarded test case. Treat `SuccessException` as a pass of that test case. Copy the warnings of the isolated context into the result.
- minor: [correctness] src/GalaxyCheck.Xunit/Core/Internal/FailureMemory.cs:201 A corrupt file, a file with a non-string value, or a file above 1 MB turns the failure memory off with no message. `Read` returns no entries, and `Update` leaves the file as it is, so no later run repairs the file. No code removes the entry of a renamed test, so the file only grows toward the 1 MB limit. Fix: on a file that does not parse, write one warning to the test output and replace the file with the new entry. Remove the entries of tests that no longer exist when the file grows past a limit, or document the limit and the manual cleanup.
- minor: [architecture] src/GalaxyCheck.MSTest/Internal/Infrastructure/MSTest/MSTestAdapter.cs:160 Each test case of an MSTest property is one `InvokeAsync` call. So MSTest builds the class and runs `[TestInitialize]` and `[TestCleanup]` for each case and for each shrink. A scratch run of 7 properties built the class 640 times. `[Timeout(300)]` limits each case and not the property, so a property of 100 cases of 5 ms passed after 559 ms. NUnit runs `[SetUp]` one time for each property, so the two packages differ. Fix: document the per-case lifetime and the per-case timeout in `docs/llms.txt` and the README, or apply the timeout of the method to the whole property.
- minor: [correctness] src/GalaxyCheck.NUnit/Internal/Infrastructure/NUnit/Commands.cs:64 `AcceptPartialRows` makes each not-runnable row runnable when it has arguments, whatever NUnit's reason was. `[TestCase("a")]` on an `int` parameter then fails with the raw text "Object of type 'System.String' cannot be converted to type 'System.Int32'" from `WithDataRow` (src/GalaxyCheck.Xunit/Core/Internal/PropertyInitializer.cs:113). The text names neither the row nor the parameter, and it has no `Fix:` line. Fix: clear only the reasons of too few arguments and of a return value. In `WithDataRow`, check each row value with the conversion of `PropertyExamples.TryConvert`, and throw a message that names the parameter.

Checked with no finding: in NUnit, `[SetUp]` and `[TearDown]` run one time for each property and for each row. Console output and `TestContext.Out` reach the result. `Property.Precondition` discards a case. `[CancelAfter]` behaves as on a plain `[Test]`. A `[TestCase]` row with fewer values than parameters runs under `ParallelScope.All` and under a `--filter` run, and `--list-tests` lists each row. A `[TestCaseSource]` row of objects with no C# form gets a distinct key. In MSTest, `Property.Precondition` discards a case in the void and the `Task` forms. `[TestInitialize]`, `[TestCleanup]`, the constructor, and `TestContext` work for each case. Console output and `TestContext` messages reach the result. Failure memory keeps all 60 entries when 60 failing tests run with `ParallelScope.All` in the net10.0 and net11.0 processes at the same time, in three runs out of three. A failing test after a saved replay that passes saves its new replay. `[Replay]` skips the saved entry and the examples. Examples convert widened numbers and enums, reject a lossy number and a null for a value type, skip a `CancellationToken` parameter, and do not shrink. The xunit v2, xunit v3, and TUnit runners only pass the failure memory configuration on.
