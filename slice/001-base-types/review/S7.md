# Review of S7 (stateful testing), round 1

- major: [requirement] src/GalaxyCheck/Stateful/Stateful.cs:180 An exception that the command expects fails the property. The filter `when (!command.Expects(ex))` does not catch an expected exception, so the exception leaves `Run` and the runner reports it as a failure. A probe confirmed it: a command whose `Run` throws an `ArgumentException` and whose `Expects` returns true for it fails after 2 tests, and its report has no command list. R43 and StatefulRun.T3 say that only an exception that the command does not expect fails. Fix: catch each exception. Throw `StatefulCommandFailedException` only when `Expects` is false. Else go on to `NextModel` and `Postcondition`, so that the model advances as the command defines.
- major: [security] src/GalaxyCheck/Runners/ExampleRenderer.cs:152 The text of `ToString()` goes into the report with no change. Two places use it: the "Counterexample as C#" section (through the fallback of `CounterexampleAsCSharpLines`) and the command list of `StatefulCommandFailedException` (Stateful.cs:220). A probe gave a command a `ToString()` with a newline and code, for example `X"); System.IO.File.Delete("x"); //`, then `2. Fake <- failed`, then `Counterexample as C#:` and `evil();`. The report then held a false `<- failed` line, a false "Counterexample as C#" header, and the code as lines of the C# section. The security floor of interface.md says that the C# expression cannot hold code from a value. Fix: (1) Give the command sequence no C# expression in the C# section, for example a comment line that says that the value has no C# expression. (2) In the renderer and in the command list, escape newlines and other control characters in the text of `ToString()`, so that each command stays on its own numbered line.
- minor: [requirement] src/GalaxyCheck/Stateful/Stateful.cs:191 An exception that `Postcondition` throws leaves `Run` with no change. The report then shows only `---- <message>`, with no command list and no `<- failed`. The same is true for an exception from `NextModel` in the runner. Fix: wrap an exception from `NextModel` and `Postcondition` in `StatefulCommandFailedException`, so that the report names the command (R45).
- minor: [requirement] src/GalaxyCheck/Stateful/Stateful.cs:220 When `ToString()` throws, `BuildMessage` throws the exception of `ToString()` in place of the failure. The report then shows `<Rendering failed>` for each command and `---- <the ToString message>`, and it does not name the command that failed. There is no crash and no hang. Fix: catch an exception of `ToString()` in `BuildMessage` and write a placeholder that holds the exception type.
- minor: [architecture] src/GalaxyCheck/Stateful/Stateful.cs:23 A model that is a mutable object, which `NextModel` changes in place, passes silently. `Postcondition` then gets the same object as `modelBefore` and `modelAfter`, so a postcondition that compares the two is always wrong. Fix: say in the XML comment of `NextModel` that it returns a new model and does not change its argument. The public members of `Command` also have no XML comments.
