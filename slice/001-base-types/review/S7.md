# Review of S7 (stateful testing), round 3

- minor: [security] src/GalaxyCheck/Stateful/Stateful.cs:268 An exception whose `Message` returns null now makes `CommandText.Escape` throw a `NullReferenceException`. This applies to the reasons at line 268 and line 286. A probe threw such an exception from `Run`. The property still failed with its counterexample, but the report showed "Object reference not set to an instance of an object" in place of the reason and the command list. Fix: treat a null message as empty, for example `CommandText.Escape(ex.Message ?? "")`, or let `Escape` take a null.
- minor: [security] src/GalaxyCheck/Stateful/Stateful.cs:268 The type name of an exception goes into the report with no escaping, at line 60, line 268, and line 286. A C# type name cannot hold a line break, but a type that is made at run time (`System.Reflection.Emit`) can. Fix: pass `ex.GetType().Name` through `CommandText.Escape` too.
- minor: [security] src/GalaxyCheck/Stateful/Stateful.cs:205 The generator calls `NextModel` with no guard. An exception from it there leaves the stateful report and goes to the generation error report, which shows the exception's `ToString()` with no escaping. A probe gave a `ToString()` with a newline and `2. Fake <- failed`, and the error report showed both lines as they were. This path is older than this round, and that report has no command list to forge. Fix: catch the exception in `Draw` and throw a `GenErrorSignal` with an escaped reason.
