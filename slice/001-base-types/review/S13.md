# Review of S13 (The reference suite), round 1

- minor: [architecture] src/GalaxyCheck/Gens/Internal/WideIntCore.cs:31 The wide integers (Int128, UInt128, BigInteger) still record the side before the distance, while IntCore and the exhaustive walk now record the distance first. So the rule "a value nearer to the origin is simpler on either side" and the sign flip of MergeNeighbours do not apply to the wide integers, and the two integer cores encode a value in two orders. Fix: record the distance first in WideIntCore too, with the same rule for the side of the origin, or state the difference in the remarks of the Shrinker.
- minor: [architecture] src/GalaxyCheck/Runners/Shrinker.cs:323 Normalize moves the elements of a list only when each span that holds the stop of the empty list also holds the moved run. The implementer reports the limit for a list under a filter, but the limit is wider: a list of lists with 100 to 120 outer elements and the property "the sum of the lengths is at most 10" ends with eight short inner lists from index 92 on (lengths 1, 1, 1, 1, 1, 1, 2, 3), because each outer element is its own span. The value still fails, so this is not a wrong shrink. Fix: let the pass move a run into an empty sibling collection of the same parent span, or note the limit in the summary of Normalize.
- minor: [requirement] src/GalaxyCheck/Gens/Internal/IntCore.cs:26 The new order of the choices of an integer changes the meaning of a replay string, but the replay keeps the same header (the V3 snapshots changed from "AgAhAwDoBwA=" to "AgAhA+gHAAA="). A replay string saved before this slice now decodes silently into another value. Fix: raise the version of the replay format, so that an old replay gives the error that the replay is no longer valid.
