# Review of S8 (the xunit v3 and TUnit packages), round 1

- minor: [requirement] .github/workflows/dotnet.yml:19 The CI workflow packs only GalaxyCheck, GalaxyCheck.Xunit, and the code analysis package (`PRERELEASE_PACKABLE_PROJECTS` and `PACKABLE_PROJECTS`). So CI never publishes GalaxyCheck.Xunit.V3 or GalaxyCheck.TUnit, and a user cannot get the packages of R22. No acceptance line of S8 asks for this. Fix: add the two projects to both lists.
- minor: [requirement] src/GalaxyCheck.Xunit.V3/Internal/Infrastructure/XunitV3/TestBodies.cs:70 A `[GenSnapshot]` test with more than one differing seed is one result with an `AggregateException`. GalaxyCheck.Xunit reports one result for each seed, each with its own exception. The test still fails, so R27 holds, but the failure text differs from xunit v2. The same applies to src/GalaxyCheck.TUnit/Internal/Infrastructure/TUnit/TestExecutors.cs:114. Fix: keep the single result, and throw one exception whose message lists each failing seed in the text of GalaxyCheck.Xunit.
- minor: [architecture] src/GalaxyCheck.TUnit/GalaxyCheck.TUnit.csproj:24 The framework-neutral core is in the folder of the xunit v2 project, and each package compiles it by a link into that folder. The same link is at src/GalaxyCheck.Xunit.V3/GalaxyCheck.Xunit.V3.csproj:26. A reader of GalaxyCheck.Xunit does not expect files there that three other packages build. Fix: move `Core/` to a folder of its own, for example `src/GalaxyCheck.Framework.Core/`, and link it from all three projects.
- minor: [architecture] src/GalaxyCheck.Xunit.V3/Attributes.cs:15 The constructor passes a null source file and line -1 to `FactAttribute`. So xunit v3 reports no source location for a property, and a test explorer can fall back to a worse location or show none. xunit v2 has no such argument, so no parity needs this. Fix: take `[CallerFilePath]` and `[CallerLineNumber]` parameters and pass them on, as `GenSnapshotAttribute` passes the file.

Checked with no finding: the falsified message of one seeded property ("the int is below 10", seed 0) is the same text in GalaxyCheck.Xunit, xunit v3, and TUnit. The invalid replay and invalid member error texts are the same. The method forms, `[Replay]`, `[MemberGen]`, `[Sample]`, `[GenSnapshot]`, the global configuration, `[InlineData]`, `[MemberData]` (also with values that do not serialize), and `[PropertyArguments]` behave as in xunit v2. In xunit v3, the test class is built and disposed once for each test (with `IDisposable` and with `IAsyncDisposable`), and `IClassFixture`, `ITestOutputHelper`, `BeforeAfterTestAttribute`, `Skip`, a skipped data row, `Timeout`, `TestContext.Current`, a `--filter` run, a static class, a nested class, a `[Fact]` beside a property, and a parallel run all work. In TUnit, the class is built and disposed once for each test, and `[Before(Test)]`, `[After(Test)]`, `[Skip]`, `[Timeout]`, `[Retry]`, the console output, a nested class, a `[Test]` beside a property, a `--treenode-filter` run, and the using alias form `[Test, Property]` all work. The public API of GalaxyCheck.Xunit is the same as at 0b332fe. Each new package exposes only the types of interface.md: the attributes, `SuppressHealthCheckAttribute`, `ExampleAttribute`, and the configuration interfaces. TUnit also has `PropertyTestAttribute` and `PropertyArgumentsAttribute`. Each pack has `lib/net10.0` and `lib/net11.0`, and it depends only on GalaxyCheck and on `xunit.v3.extensibility.core` or `TUnit.Core`, with no runner.
